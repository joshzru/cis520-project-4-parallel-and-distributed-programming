\section*{Software Architecture}

\subsection*{Overview}

This document will evaluate three separate programs, each using three different methods of parallelization—pthreads, openmp, mpi—as the number of nodes, number of threads, and amount of memory varies.

Each implementation has been tested in batches of ten, measuring their runtime in seconds, maximum memory usage in kilobytes, and their average cpu utilization as a percentage.

\subsection*{File I/O}

The pthreads and openmp implementations read in the wiki dump text file differently than the mpi implementation due to some architectural decisions.

The pthread and openmp implementation read the wiki dump text file in 20,000 lines at a time. With an average character count per line of 1,700, this amounts to approximately $\frac{20,000 \cdot 1,700}{1,048,576} = 32.42$ MB. Notably, this size fits comfortably in the smallest amount of memory we test.

The mpi implementation reads the entire wiki dump text file in at once. Since the file is approximately $1.7$ GB, it will need at least that much memory to not run out.

Each program uses a \texttt{file\_string\_array\_t} struct, which stores the lines of the wiki dump text file as a \texttt{$**$ char}.

\subsection*{Pthreads}

This implementation uses a \texttt{process\_chunk} function to spawn each pthread at for each chunk read in from the wiki dump text file. This may contribute to a hit in performance due to the overhead of having to create threads for each chunk. Each pthread modifies a global \texttt{max\_values} integer array. No locks are needed because each pthread has a mutually exclusive range of lines with each index of \texttt{max\_values} corresponding to a line.

\subsection*{Openmp}

This implementation uses a single for loop and the \texttt{\#pragma omp parallel for} preprocessor directive to parallelize the task. Each thread modifies a global \texttt{max\_values} integer array at a global \texttt{max\_values\_i} index plus their local index inside the for loop. This avoids a race condition because each thread will have a mutually exclusive range of \texttt{i} in the for loop.

\subsection*{Mpi}

This implementation uses the main process (rank 0) to load the text file into memory. Then, the \texttt{file\_string\_array} structure of the main process divides up the lines amongst all threads, and sends them to other threads using \texttt{MPI\_Send}. Doing so keeps the threads’ memory separate, avoiding a race condition, and each thread only allocates memory it will use. The max ascii values of each line in the file are sent back to an array within the main thread’s memory, which is then processed into the program’s output.

\begin{figure}[!ht]

    \caption{Effect of increasing thread count on runtime}
    \label{fig:pthread-runtime-focus}

To better understand the effect of threading, Figure~\ref{fig:pthread-runtime} isolates configurations where only the number of threads varies while other parameters remain constant.

It can be observed that increasing the number of threads results in a substantial decrease in mean runtime. It does appear as though this relationship is not linear, however, as the batch with 4 threads is not as far from the batch with 2 threads as the batch with 2 threads is from the batch with 1 thread.

\bigskip

When holding the number of threads and nodes constant, increasing memory from 64 MB to 128 MB does not significantly impact runtime. Similarly, increasing the number of nodes from 1 to 2 does not significantly impact runtime.

\section{Batch Scripts}

\subsection{pthread}

\begin{lstlisting}{language=bash}
#!/bin/bash
## Script for running project 4 in Operating System - OpenMP

## SBATCH variables
#SBATCH --job-name=openmp-test
#SBATCH --nodes=2
#SBATCH --cpus-per-task=16
#SBATCH --mem-per-cpu=128M
#SBATCH --time=00:05:00
#SBATCH --mail-type=ALL
#SBATCH --mail-user=jazrubek@ksu.edu
#SBATCH --constraint=moles
#SBATCH --partition=killable.q

## Program variables
NODES=2
THREADS=16
MEMORY="128M"
PROGRAM_NAME="3way-pthread"
PROGRAM_PATH="${HOME}/cis520-project-4-parallel-and-distributed-programming/${PROGRAM_NAME}/build/${PROGRAM_NAME}"
LOG_FILENAME="${NODES}x${THREADS}x${MEMORY}_${PROGRAM_NAME}_log.txt"
CSV_FILENAME="${NODES}x${THREADS}x${MEMORY}_${PROGRAM_NAME}.csv"
OUTPUT_FILENAME="${NODES}x${THREADS}x${MEMORY}_${PROGRAM_NAME}_output.txt"

cp $PROGRAM_PATH $TMPDIR
pushd $TMPDIR

echo "Running ${PROGRAM_NAME} with ${MEMORY} memory, ${THREADS} thread(s), and ${NODES} node(s)" >> $LOG_FILENAME

echo "Runtime (s),Max Memory (KB),CPU Usage (%)" >> $CSV_FILENAME

for i in {0..9}; do
    /usr/bin/time --format="%e,%M,%P" ./$PROGRAM_NAME $THREADS >> $OUTPUT_FILENAME 2>> $CSV_FILENAME
done

kstat --table-cpu-usage-1min "$SLURM_JOB_ID" >> $LOG_FILENAME

popd
mkdir -p $HOME/$PROGRAM_NAME/logs/
mkdir -p $HOME/$PROGRAM_NAME/output/
mkdir -p $HOME/$PROGRAM_NAME/csv/
cp $TMPDIR/$OUTPUT_FILENAME $HOME/$PROGRAM_NAME/output/$OUTPUT_FILENAME
cp $TMPDIR/$LOG_FILENAME $HOME/$PROGRAM_NAME/logs/$LOG_FILENAME
cp $TMPDIR/$CSV_FILENAME $HOME/$PROGRAM_NAME/csv/$CSV_FILENAME

\end{lstlisting}
